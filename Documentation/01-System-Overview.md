## 1. فكرة النظام

**Qurtuba Project Tracker** هو نظام ويب مؤسسي لإدارة المشاريع والمهام، يعمل بالكامل عبر **لوحة تحكم إدارية حديثة** (Filament 3) على المسار `/admin`. يتيح النظام إنشاء المشاريع وتقسيمها إلى مهام، وتوزيع هذه المهام على **الأقسام** و**الموظفين**، ومتابعة التقدّم والتأخير والعوائق، وإصدار تقارير قابلة للطباعة والتصدير — كل ذلك بواجهة **عربية كاملة (RTL)**.

النظام مطبَّق فعليًا على مشروع **«تشغيل مباني قرطبة»** (مدارس غراس الأخلاق الأهلية)، لكنه مصمَّم كـ **منتج عام** قابل لإعادة البيع والاستخدام: الهوية البصرية (اسم النظام، الشعار، اللون، نمط السايد بار) قابلة للتغيير بالكامل من داخل النظام دون لمس الكود.

---

## 2. أهداف النظام

1. **مركزية إدارة المشاريع**: مصدر واحد للحقيقة لكل المشاريع والمهام وحالتها.
2. **المساءلة والشفافية**: ربط كل مهمة بمسؤول وقسم، وتسجيل كل تغيير في **سجل تدقيق** تلقائي.
3. **متابعة التأخير والعوائق**: رصد المهام المتأخرة، أسبابها، واحتياجاتها (دعم/اعتماد/ميزانية/قرار).
4. **التعاون بين الأقسام**: مهمة واحدة قد تشترك فيها عدة أقسام بأدوار مختلفة (تنفيذ/موافقة/دعم...).
5. **رؤية إدارية فورية**: لوحة تحكم بمؤشرات ورسوم بيانية + تقارير جاهزة للطباعة والتصدير.
6. **تجربة استخدام احترافية**: عربية كاملة، تصميم عصري، متوافق مع الجوال، وهوية بصرية مرنة.

## 3. المشكلة التي يحلّها

| المشكلة قبل النظام | الحل داخل النظام |
|---|---|
| تشتّت المهام في جداول Excel ورسائل منفصلة | قاعدة بيانات مركزية واحدة + لوحة موحّدة |
| غياب المساءلة (من المسؤول؟) | كل مهمة لها مسؤول + قسم رئيسي + أقسام معنية |
| عدم وضوح التأخيرات وأسبابها | حقول تأخير + مؤشرات «متأخر؟» + تقرير تأخير مخصّص |
| صعوبة معرفة عبء كل موظف/قسم | تقرير أداء الموظفين + تقرير الأقسام |
| لا يوجد سجل لمن غيّر ماذا ومتى | سجل تدقيق تلقائي لكل تغيير |
| صعوبة إخراج تقارير للإدارة | طباعة/PDF + تصدير Excel بنقرة |

## 5. الأدوار والصلاحيات

النظام يعتمد ثلاثة أدوار مخزّنة في عمود `users.role`، وتُطبَّق عبر **Policies** (`ProjectPolicy`, `TaskPolicy`) و`canAccess()` في صفحات Filament.

| الدور | المشاريع | المهام | المستخدمون/الأقسام | الإعدادات وسجل التدقيق | التقارير |
|---|---|---|---|---|---|
| `admin` | كامل | كامل | كامل | كامل | كل الأنواع |
| `manager` | إنشاء/تعديل (حذف لما أنشأه) | كامل | عرض | — | كل الأنواع |
| `user` | — | مهامه والمرتبطة به فقط | — | — | تقرير مهامه فقط |

**تفاصيل مهمة من الكود:**
- الوصول إلى اللوحة يتطلب `is_active = true` (عبر `User::canAccessPanel()`).
- حذف مشروع: للأدمن أو منشئ المشروع فقط (`ProjectPolicy::delete`).
- المستخدم العادي يرى مهمة إذا كان **مسؤولها** أو **منشئها** (`TaskPolicy::view`).
- صفحة التقارير مفتوحة لكل مستخدم مسجّل، لكن `user` مقيّد بنطاق **«مهامي»** فقط.

## 8. المفاهيم والحالات الأساسية

### حالات المشروع/المهمة (`status`)
`pending` قيد الانتظار · `in_progress` قيد التنفيذ · `completed` مكتمل · `cancelled` ملغى.

### الأولوية (`priority`)
`low` منخفض · `medium` متوسط · `high` عالٍ · `urgent` عاجل.

### مسؤولية القسم في المهمة (`task_departments.responsibility`)
`primary` مسؤول رئيسي · `execution` تنفيذ · `financial` قرار/اعتماد مالي · `advisory` استشاري · `approval` موافقة · `support` دعم.

### خصائص محسوبة (Computed) مهمة
- **المهمة متأخرة (`is_delayed`)**: لها `due_date` ماضٍ وحالتها ليست مكتملة/ملغاة.
- **أيام التأخير (`days_delayed`)**: الفرق بين تاريخ الاستحقاق واليوم.
- **المهمة محجوبة (`is_blocked`)**: لها اعتمادية (Dependency) غير منجزة.
- **نسبة إنجاز المشروع (`completion_rate`)**: المهام المكتملة ÷ إجمالي المهام.

## 9. سير العمل داخل النظام (Workflows)

### 9.1 دورة حياة المهمة
```
إنشاء المهمة (pending)
   └─ إسناد لمسؤول + قسم رئيسي + أقسام معنية
        └─ بدء التنفيذ (in_progress) + تحديث نسبة الإنجاز
             ├─ تسجيل عوائق / أسباب تأخير عند الحاجة
             └─ اكتمال (completed) أو إلغاء (cancelled)
```
عند كل خطوة يسجّل `TaskObserver` نشاطًا في السجل الزمني ويُرسل إشعارات تلقائية (للمسؤول والمنشئ).

### 9.2 التعاون متعدد الأقسام
مهمة واحدة → قسم رئيسي (`tasks.department_id`) + عدة **أقسام معنية** (`task_departments`) لكلٍّ منها نوع مسؤولية. فلتر القسم في جدول المهام يجلب المهمة سواء كان القسم رئيسيًا أو معنيًا.

### 9.3 المتابعة والتقارير
```
الإدارة → لوحة التحكم (مؤشرات) → التقارير (فلترة بالنطاق/القسم/الحالة) → طباعة/PDF أو Excel
```

### 9.4 المساءلة (Audit)
أي إنشاء/تعديل/حذف على مشروع أو مهمة أو مستخدم أو قسم → `AuditObserver` يكتب سجلًا (من، ماذا، متى، وما الحقول التي تغيّرت).

## 10. لمحة معمارية سريعة

```
المتصفح (RTL, Cairo)
   → Filament Panel (/admin)  ← Livewire/Alpine
      → Resources / Pages / Widgets
         → Policies (صلاحيات)
         → Models (Eloquent)  ← Observers (Audit/Task) ← Services (Notification/Report)
            → MySQL
```
